NAME

csbench − batteries included command−line benchmarking tool

SYNOPSIS

csbench [options] command...

DESCRIPTION

Command−line benchmarking tool which includes:

* Statistical analysis across multiple runs.
* Statistical comparison between multiple benchmarks.
* Support for arbitrary shell commands.
* Benchmarks can be executed in rounds of several consecutive runs.
* Warmup runs can be executed before each benchmark or round.
* Benchmarks can receive common input either from file or string specified in command−line.
* Benchmarks can be parameterized with variable, substituted in command string or input file name or input string.
* Benchmarks can include custom measurements, whose values are extracted from each command’s stdout.
* Benchmarks’ measurements can include information from "struct rusage" (see getrusage(2)).
* Benchmarks’ measurements can include performance counter metrics, such as number of cycles, instructions, branches taken and branches missed.
* Parallel execution.
* Plotting functionality.
* Generate thorough reports in various formats: HTML, Command−line, Markdown.
* Export results to various formats: CSV, JSON.

OPTIONS

Benchmark stop condition options

−R, −−runs NUM

Run each benchmark exactly NUM times in total (not including warmup). When set, −−time−limit, −−min−runs and −−max−runs have no effect.

−T, −−time−limit DURATION

Run each benchmark for at least DURATION seconds in total. Affected by −−min−runs and −−max−runs. DURARION is a real number optionally followed by measurement units ("s", "ms", "us", "ns"). If units are not specified, seconds are assumed.

−−min−runs NUM

Run each benchmark at least NUM times.

−−max−runs NUM

Run each benchmark at most NUM times.

Warmup options

−−warmup−runs NUM

Perform exactly NUM warmup runs. When set, −−warmup, −−min−warmup−runs and −−max−warmup−runs have no effect.

−W, −−warmup NUM

Perform warmup for at least NUM seconds in total. Affected by −−min−warmup−runs and −−max−warmup−runs. DURARION is a real number optionally followed by measurement units ("s", "ms", "us", "ns"). If units are not specified, seconds are assumed.

−−min−warmup−runs NUM

Perform at least NUM warmup runs.

−−max−warmup−runs NUM

Perform at most NUM warmup runs.

−−no−warmup

Disable warmup.

Round options

−−round−runs NUM

In a single round perform exactly NUM runs. When set, −−round−time, −−min−round−runs and −−max−round−runs have no effect.

−−round−time NUM

Each benchmark will be run for at least NUM seconds in row. Affected by −−min−round−runs and −−max−round−runs. DURARION is a real number optionally followed by measurement units ("s", "ms", "us", "ns"). If units are not specified, seconds are assumed.

−−min−round−runs NUM

In a single round perform at least NUM runs.

−−max−round−runs NUM

In a single round perform at most NUM runs.

−−no−rounds

Do not split execution into rounds.

Benchmark setup options

−−common−args STR

Append STR to each benchmark command.

Example:

csbench −−common−args ’-Wall -Werror -pedantic -O2 main.c’ gcc clang

−S, −−shell SHELL

Set the shell to be used for executing benchmark commands. Can be both name of shell executable, like "bash", or a command like "bash −−norc". Either way, arguments "-c" and benchmark command string are appended to shell argument list. Alternatively, SHELL can be set to "none", or "inherit". If set to "none", commands will be executed directly using execve(2) system call, avoiding shell process startup time overhead. If set to "inherit", uses the shell set in SHELL variable of calling process.

−N

An alias no −−shell=none.

−P, −−prepare CMD

Execute CMD in shell before each benchmark run. CMD may contain parameter substitutions.

Example:

csbench −−prepare=’make clean’ make

−−round-prepare CMD

Execute CMD in shell in the beggining of each round, before the warmup. CMD may contain parameter substitutions.

−j, −−jobs NUM

Executed benchmarks in parallel using NUM system threads. By default, benchmarks are executed only in one thread.

−i, −−ignore−failure

Do not abort benchmarking when benchmark commands finishes with non−zero exit code.

−s, −−simple

Preset to run benchmarks using system thread count obtained by executing nproc(1), for 1 second without warmup and rounds.

−−shuffle−runs

Randomize the order in which benchmarks are run. By default they are run round-robin from first to last.

Command input and output options

−−input FILE

Specify file that will be used as input for all benchmark commands. FILE can include variable substitutions.

−−inputs STR

Specify string that will be used as input for all benchmark commands. STR can include variable substitutions.

−−inputd DIR

Specify directory, all files from which will be used as input for all benchmark commands. This effectively works as macro, specifying "−−input {file} −−param file/...", where "−−param" option is passed a list of files contained in DIR.

−−no−input

Disable input (use /dev/null as input). This is a default option.

−−output KIND

Control where stdout and stderr of benchmark commands is redirected.

KIND can be:

null

Redirect output to /dev/null (default).

inherit

Don’t redirect the output at all.

Measurement options

−−meas MEAS

List of built-in measurements to collect.

MEAS is comma-separated list of measurement names, which can be of the following:

wall

wall clock time

stime

kernel CPU time

utime

userspace CPU time

maxrss

maximum size of resident set size

minflt

minor page fault count

majflt

major page fault count

nvcsw

voluntary context switch count

nivcsw

involuntary context switch count

cycles

CPU cycle count

instructions

CPU instruction count

branches

CPU taken branch count

branch-misses

CPU branch misdirection count

Measurements "stime", "utime", "maxrss", "minflt", "majflt", "nvcsw", "nivcsw" are obtained from "struct rusage" (see getrusage(2)). Measurements "cycles", "instructions", "branches", "branch-misses" are obtained using system performance counters (see perf_event_open(2) on Linux). Default measurements are "wall", "stime", "utime".

Example:

csbench −−meas cycles,instructions ls

−−custom NAME

Add custom measurement with name NAME. This measurement parses stdout of each benchmark command and interprets it in seconds.

−−custom−t NAME CMD

Add custom measurement with name NAME. This measurement pipes stdout of each command to CMD, parses its output as a single real number and interprets it in seconds.

−−custom−x NAME UNITS CMD

Add custom measurement with name NAME. This measurement pipes stdout of each command to CMD, interprets its output as a single real number and interprets it in UNITS.

UNITS can be one of the following:

s

seconds

ms

milliseconds

us

microseconds

ns

nanoseconds

b

bytes

kb

kilobytes

mb

megabytes

gb

gigabytes

none

no units

<UNITS−NAME>

Use <UNITS−NAME> as name

−−custom−re NAME UNITS RE

Add custom measurement with name NAME. This measurement regular expression RE to extract data from stdout of each command, parses first subexpression as a single real number and interprets it in UNITS.

Example:

csbench ’echo hello, $RANDOM’ −−custom−re m s ’hello, ([0-9.]+)’

−−no−default−meas

Do not use default measurements (which are "wall", "stime", "utime").

Parameterization options

−−param STR

STR is of the format <i>/<v>. Add benchmark parameter with name <i>. <v> is a comma−separated list of parameter values. Parameter can be substituted in any command string, in strings supplied to −−input, −−inputs and −−common−args options.

Example:

auto

select csbench −−param n/100,200,400,800 ’python3 quicksort.py {n}’

−−param-range STR

STR is of the format <i>/<n>/<m>[/<s>]. Add benchmark parameter with name <i>, whose values are in range from <n> to <m> with step <s>. <s> is optional, default is 1.

Example:

csbench −−param-range n/100/500/100 ’python3 quicksort.py {n}’

Alternative mode options

−−load−text

Load benchmark data from CSV files listed in command-line. CSV can either be generated by csbench using −−csv option, or any external source. This option changes interpretation of command... from list of commands to benchmark to list of CSV file names.

Format of CSV files is the same as generated by csbench for "bench_raw_*.csv" files. First line should contain measurement names, all other lines should contain values for these measurements.
Example:

csbench −−load−text .csbench/benches_raw_0.csv .csbench/bench_raw_1.csv

Format description:

# extract=’{name} n={n}’ meas=<measname> units=<unit>
<bench1>,<val1>,<val2>,...
<bench2>,<val1>,<val2>,...
Header (optional, #-prefixed)
- extract - pattern for parsing benchmark names.
- {name} - group name
- {<var>} - variable placeholder for parameter analysis
- meas - label of the measurement (e.g. time, size).
- units - measurement units: ns, us, ms, s, b, kb, mb, gb, none.
Data lines
Start with benchmark name (<bench>). Then values, e.g. 1,2,3...
Simple Example:
option1,1,2,3
option2,4,5,6
Complex Example:
# extract=’{name} n={n}’ meas=mymeas units=ns
a n=1,1,2,3
a n=2,4,5,6
b n=1,10,20
b n=2,100,200

Note that all options listed above in this man page are not usable in this mode. All the options listed below can be used (rename, set baseline, generate plots, export data etc.).

−−load−bin

Load output from files in custom binary format. These files can either be generated by csbench using −−save−bin option, or any external source. This option changes interpretation of command... from list of commands to benchmark to list of binary file names. If command... list is empty, directory specified with −−out−dir is used. Command can either be name of binary file, or directory that contains data.csbench file. This matches the output format of −−save−bin option.

Binary file format lacks specification. Look into csbench sources for additional information.

Binary file saves all information about benchmark and can be used to load it later. Generally, the report generated when running benchmark is the same that will be generated when loading saved binary data for this benchmark. If multiple files are listed, their results are merged. This can be used to do comparisons of complex multi-step benchmarks.
Example:

csbench ls −o bench1 −−save-bin

csbench pwd −o bench2 −−save-bin

csbench −−load−bin bench1 bench2

or

csbench ls −−save−bin−name bench1.data −−save−bin

csbench pwd −−save−bin−name bench2.data −−save−bin

csbench −−load−bin bench1.data bench2.data

Note that all options listed above in this man page are not usable in this mode. All the options listed below can be used (rename, set baseline, generate plots, export data etc.).

Analysis options

−−nrs NUM

Use NUM resamples when computing 95% confidence intervals using bootstrapping. Default value is 10000.

−−stat−test TEST

Specify statistical test to be used to calculate p-values. Possible values for TEST are:

mwu

Mann-Whitney U-test (default).

t-test

Welch’s t-test.

Note that none of these tests is generally better. Welch’s t-test (with null hypothesis u1=u2) is more correct statistically, but provides bad results when run count is small (less than 20-30), however becomes increasingly better with bigger run counts. MWU (with null hypothesis that distributions are the same), on the other hand, provides consistent results up to big run counts (˜1000). Note that number of resamples used to calculate Welch’s t-test p-value is controlled by −−nrs option.

−−regr

Perform linear regression of measurements in terms of benchmark parameters.

Output options

−−baseline NUM

Use benchmark with number NUM (starting from 1) as baseline in comparisons.

−−baseline-name NAME

Use benchmark with name NAME as baseline in comparisons.

−−rename NUM NAME

Rename benchmark with number NUM (starting from 1) to NAME. This name will be used in reports instead of the default one, which is a command string.

−−rename-name OLD_NAME NAME

Rename benchmark with name OLD_NAME to NAME.

−−rename-all NAMES

Rename all benchmarks. NAMES is a comma-separated list of new benchmark names, whose length must be equal to benchmark count.

Example:

csbench −−rename−all one,two ls pwd

−−sort METHOD

Specify order of benchmarks in reports.

METHOD can be one of the following:

auto

sort by speed if baseline is not set, keep original order otherwise (default).

command

keep original order.

mean-time

sort by mean time.

−o, −−out−dir DIR

Place all outputs to directory DIR. Default value is ".csbench".

−−plot

Generate plots to output directory. "python3" with "matplotlib" installed must be available at search path. Generates file "plots_map.md" containing list and descriptions of generated files.

−−plot−src

Save sources used to generate plots to output directory.

−−plot−backend BACKEND

Select backend used to generate plots. Possible values for BACKEND are:

auto

Select best available backend (default).

matplotlib

Use python with "matplotlib" library.

gnuplot

Use gnuplot.

Note that gnuplot version in inferior to matplotlib in terms of visuals. That is way matplotlib is chosen if available when using "auto" option.

−−html

Generate HTML report. Implies −−plot.

−−csv

Save benchmark results to CSV files placed in output directory. Also generates file "csv_map.md" containing list and descriptions of generated files.

−−json FILE

Export benchmark results to FILE in JSON format.

−−save−bin

Save data in custom binary format. If −−save−bin−name option is not used, data is saved to file data.csbench placed in directory specified with −−out−dir. For additional information see −−load−bin option.

−−save−bin−name NAME

Override file that will be used to save binary data (using −−save−bin option) to. NAME is new file name.

Miscellaneous options

−−color WHEN

Use colored output. Possible values for WHEN are "never", "auto", "always".

−−progress−bar WHEN

Display dynamically updated progress bar when running benchmarks. Possible values for WHEN are "never", "auto", "always".

−−progress−bar-interval TIME

Set redraw interval of progress bar to TIME. Default is 100ms (100 milliseconds). TIME is a real number optionally followed by measurement units ("s", "ms", "us", "ns"). If units are not specified, seconds are assumed.

−−plot−debug

Do not silence output of program which is used to make plots.

−−python−executable EXE

Use file EXE as python executable when making plots. Default is "python3".

−−clear−out

Clear out directory (specified using −−out−dir) before execution.

−−help

Print help message.

−−version

Print version.

EXAMPLES

Basic benchmark of ’ls’:

csbench ls

Comparison benchmark between ’ls’ and ’lsd’:

csbench ls lsd
